# 命理中西互证方法论（zhongxi-huzheng）

## 何时触发

- 用户提供出生信息（公历/农历 + 时间 + 出生地 + 性别）要求测算
- 用户问"某年/某月运势如何"、"事业/财运/感情转折点"
- 用户要求"多系统交叉验证"、"中西合璧"、"结合星座"
- 本 skill 是**流程编排层**，排盘计算交给引擎，解读由模型完成

## 核心原则（必守）

1. **东算应期，西算结构**：东方体系（八字大运流年/紫微大限/奇门时局）强于"什么时候好"，西方体系（占星本命相位/推运/返照）强于"你是哪种人、事件结构如何"——各用所长
2. **独立计算，交叉验证**：两体系**各自独立算出结论**，再对照。同向 → 高置信共识；异向 → 如实并列，标注"体系分歧，仅供参考"
3. **古籍为纲**：八字部分严格以《滴天髓》《子平真诠》《穷通宝鉴》《三命通会》《渊海子平》为据（原文引自 ctext.org / zh.wikisource.org），凡古籍无据者不妄断
4. **禁套话禁迎合**：禁止"大器晚成""黄金十年"式无据套话；用户实况反馈是校验用神判断的最高证据（运岁相济），反馈与理论矛盾时**修正理论，不硬圆**
5. **时辰分歧如实呈现**：西部出生（新疆/西藏等经度 <110°E）必须做真太阳时修正，两版（钟表时/真太阳时）并列，以用户确认的记录方式为基准

## 完整流程（5 步）

### Step 1：收集信息 + 时辰预处理

```
必收：出生日期（公历/农历）、出生时间（精确到小时即可，越准越好）、出生地、性别
处理：
1. 农历→公历（lunar_python Solar.fromYmdHms）
2. 真太阳时修正：经度 <110°E 时计算偏移（lon_offset=(lon-120)*4 分钟 + 均时差 EoT）
3. 判定时辰：真太阳时对照十二时辰（子23-1/丑1-3/寅3-5/卯5-7/辰7-9…）
4. 若修正后时辰与钟表时辰不同 → A/B 两版并列，请用户确认记录方式
```

### Step 2：东方体系排盘（应期）

| 需求 | 首选引擎 | 回退 |
|---|---|---|
| 八字 | mingyu MCP `bazi_prompt` / 本地 bazi-python 详盘 | bazi-ziwei 算法层 |
| 紫微 | mingyu MCP `ziwei_prompt` | bazi-ziwei calculator |
| 奇门 | mingyu MCP `divine_qimen` | 手工推算 |
| 流年 | 大运（阴男逆行）+ 流年干支喜忌（用神框架） | 详盘引擎输出 |

**八字论断要点**：
- 定日主强弱、格局（月令本气）、调候用神（穷通宝鉴按月查）
- 大运顺逆（阳男阴女顺行/阴男阳女逆行）、起运年龄（节气精确计算）
- 流年干支对用神的作用：生用神吉，克泄用神凶；**运岁相济**（大运凶流年救→顺，如 2020-2023 庚辛壬癸金水连珠补壬水）
- 应期法则：《滴天髓》"坐寅怕申冲则根动"类——流年冲日支/用神是变动应期

### Step 3：西方体系排盘（结构）

**引擎**：mingyu-core 本地调用（MCP 不在会话时）：

```js
// 本命盘（在 C:\Users\Administrator\Documents\mingyu 下运行）
import { generateAstrolabe } from 'mingyu-core/divination/astrolabe';
generateAstrolabe({ year: '1985', month: '6', day: '8', hour: '6', minute: '0',
  latitude: '42.3', longitude: '88.5', timeZoneId: 'Asia/Shanghai' });

// 流年推运（行运+太阳返照+次限+太阳弧）
import { buildAstrolabeScopeContext } from 'mingyu-core/divination/astrolabe-scope';
buildAstrolabeScopeContext(natal, 'yearly', '2028');
```

**⚠️ 参数坑（实测踩过）**：
- astrolabe 数值参数**必须是字符串**（`year: '1985'` 而非 1985），timezone 用 `timeZoneId`（IANA 名，处理历史夏令时）；`'+08:00'` 格式会被拒
- `buildAstrolabeScopeContext` 的日期参数用 `'YYYY'` 格式（如 '2028'），非完整日期
- qimen 的 `generateQimen` 第一参数传 **Date 对象**，非字符串
- 返回结构：`planets[]`（name/label/sign/degree/minute/house/retrograde）、`angles[]`（Ascendant/Midheaven…）、`houses[12]`、`aspects[]`（body1/type/body2/deviation/orb）、`summary`（elements/modalities/retrograde/patterns）

**解读要点**：
- 上升/太阳/月亮 + 1宫群星 = 人格结构（如双子1宫群星=信息型人格）
- 外行星行运（土星/天王/冥王）过本命敏感点（上升/天顶/太阳）= 结构性事件年
- 太阳返照 = 年度主题；次限推进 = 内在演化；太阳弧 = 长期周期
- 金火相位 ↔ 感情冲动；土星相位 ↔ 事业地位；天王相位 ↔ 身份重塑

### Step 4：交叉验证 + 输出

**互证表格式**：

| 年份 | 八字流年 | 占星推运 | 共识 |
|---|---|---|---|
| 2026 | 丙午火旺宜守 | 金星冲月亮（情业拉锯） | 🟢 守住 |
| 2027 | 丁未换运重组 | 天王星合上升（身份重塑） | 🟢 主动变 |
| 2028 | 戊申金生水（转机） | 土星拱天顶+金星合上升（起势） | 🟢 结构性向上 |

**输出三块式**：
1. 📌 **共识项**（两体系同向）：高置信，重点给
2. 🔀 **分歧项**（两体系异向）：如实并列，标注"体系分歧，仅供参考"
3. 🧭 **行动建议**（可执行、分时点）

**附参数完整度声明**：时辰精确度、经度修正与否、推运基准日期，影响 confidence 即降级声明

### Step 5：归档

- 完整报告存 Obsidian `命理档案/` 目录（主档案 + 流年判断姊妹篇）
- 主档案结构：基本信息→八字→紫微→星盘→四维深挖→古籍论证版→说人话版→商业模式论证→占星推运
- 用户实况反馈（如"35-40很顺"）是**最高校验证据**，追加进档案并修正理论

## 实测案例（2026-08-07，可复现）

**命例**：男 示例命主甲 辰时 新疆某地（88.5E, 42.3N）
- 八字（辰时）：乙丑 壬午 戊寅 丙辰——火炎土燥，用神壬水（穷通宝鉴"先看壬水"），忌火土
- 大运：戊寅（32-42最燥）→丁丑（42-52）→丙子（52-62最得力）
- 占星：上升双子7°37'，太阳双子17°1宫，月亮水瓶10宫——信息型人格（与壬水偏财吃信息差同构）
- 互证结论：2026 守（金星冲月/丙午火年）、2027 变（天王合上升/丑未冲）、2028 起（土星拱天顶/申金生水）
- **用户实况校验**：35-40 很顺（2020-2023 庚辛壬癸金水连珠补用神）→ 修正了"戊寅运全凶"的粗判，确立"运岁相济"法则

## 陷阱与教训

1. **勿用 LLM 手排**：排盘必须走算法引擎（mingyu/lunar_python/Yiqi），LLM 手排必错
2. **时辰是硬伤**：新疆西藏出生必须真太阳时修正，辰时卯时差一柱，全盘皆变
3. **古籍引文要核实**：从 ctext.org / zh.wikisource.org 抓原文核对，不凭记忆引用
4. **民间口诀要考据**：如"桃花不采变成财"非古籍原文，是民间演绎——分清经书原文与江湖口诀
5. **用户反馈 > 理论**：理论预测与用户实况矛盾时，修正理论（运岁相济），不硬圆
6. **推运基准**：行运按出生地时区（Asia/Shanghai）中午计算，输出 promptText 即含完整证据链
