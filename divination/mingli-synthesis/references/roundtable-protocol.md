# 圆桌合参协议（Roundtable Protocol）

> 来源：吸收自 GitHub `MTKEN368/liu-he-xuan-ji`（六合玄机，MIT）的「五轮圆桌论证」机制，**经改造后并入本 skill**。
> **改造要点（关键差异）**：六合玄机让 AI **手算排盘**后圆桌；我们**排盘一律走引擎（确定性）**，AI 只在**解读层**扮演各派——避免"排盘算错、圆桌再漂亮也是错地基"的致命弱点（其自身免责声明亦承认"紫微安星、大六壬九宗门可能存在误差"）。
> 落地日期：2026-09-21

---

## 一、前提铁律

1. **引擎算盘**：四柱/卦象/局盘一律由引擎产生（`mingyu` MCP、`mingpan` MCP、`bazi-paipan/scripts/zero-dep/pai_pan.py`）；**AI 绝不手工推算**。
2. **多引擎交叉验证**：四柱至少两路独立引擎对照一致（推荐四路：mingyu / iztro / pai_pan.py / mingpan）；不一致即参数有误，先查参数再谈解读。
3. **信息不全不强推**：时辰未定 → 降级（前三柱+标注待定）；缺问事时刻 → 用当前时刻并注明。

## 二、门派适配矩阵（按问题类型启体系）

| 问题类型 | 启用体系 | 必需信息 |
|---|---|---|
| 一生格局/命盘 | 八字（子平+盲派双口径）+紫微+占星 | 生辰+性别 |
| 流年/流月/流日 | 八字流年月日+紫微流年月 | 生辰 |
| 单次决策问事 | 奇门+梅花（可加六爻/大六壬） | 问事时刻+事项 |
| 寻人/寻物/官非诉讼 | 奇门（`qimen_yongshen` 14 事类）+六爻 | 问事时刻 |
| 婚恋/合盘 | 八字合盘+紫微双盘+占星合盘 | 双方生辰 |
| 住宅/办公风水 | 八宅+玄空+流年飞星 | 坐向+建造年+命卦 |
| 择日/择时 | 黄历择日+奇门 | 事项+时段+参与人生辰 |
| 健康/情绪 | 八字（五行偏枯）+紫微疾厄 | 生辰 |

默认：命盘类=八字+紫微+占星；问事类=奇门+梅花。用户指定则从其要求。

## 三、五轮圆桌

**第 1 阶段（隔离解读）**：各派独立推演，**严禁交叉污染**——本派只用本派理论与判据（子平=格局/用神/调候；盲派=象法/刑冲/宾主；紫微=星曜/四化/宫位；奇门=门/星/神/格；梅花=体用/互变；六爻=用神/动变/月建）。

**R1 立论** — 每派输出：核心判断（吉/凶/中平/吉凶参半）+ **2-3 条具体证据** + 应期
- ✅ 合格证据："用神午火月破日克，根基不稳"｜"开门落坤二逢死门，流程受阻"
- ❌ 不合格："看着不太好"｜"气场不合"

**R2 质询** — **每派至少质询两派**：先求同，再指异，**必须引本派技术理由**
- 求同式："奇门所断应期与我爻象暗合，皆指向冬月"
- 指异式："紫微以流年命宫论吉，然我八字看此年伤官见官，非吉"

**R3 辩论** — 聚焦 R2 暴露的 **top 2-3 矛盾**，**目标是搞清"为什么分歧"**（体系视角差异），不是只列出"有分歧"
- 输出句式："分歧根源：八字重'我'（日主强弱），紫微重'位'（宫位吉凶）——同一件事两套坐标系，非真矛盾"

**R4 修正** — 各派可调整结论，**修正须留痕**：`原判断 → 修正后 → 触发修正的证据`

**R5 综合** — 归并到统一维度（事业/财运/感情/健康/性格/时机，按问题裁剪）：
- **共识项**：≥3 独立体系一致 → 最高权重
- **部分支持**：2 体系一致 → 中等权重
- **分歧项**：原样并列各方逻辑，**不强行调和**，注明"体系视角差异"

## 四、置信度三档（必标）

| 档位 | 成立条件 | 输出要求 |
|---|---|---|
| **高（铁断）** | ≥3 体系一致 **且** 有古籍明文/引擎证据链 **且** 能给可验证的时间窗或事件 | 敢锁死；不给"可能/也许"式回退话术（铁断纪律） |
| **中（倾向）** | 2 体系一致，或多数一致但有明确分歧 | 给倾向 + 标注分歧点（谁不同意、为什么） |
| **低（待验证）** | 信息不全（时辰未定等）/仅单一体系/严重冲突 | 标注**待验证条件**（什么现实信息能确认或推翻） |

三档都要在报告中显式标出（数据契约 `confidence` 字段 + 正文档位标签）。

## 五、输出模板（圆桌纪要式）

```markdown
## 圆桌合参 · {日期} · {问题}
> 引擎：{mingyu/mingpan/…} ｜ 参数完整度：{已定/时辰待定/…}

### 一、各派立论
| 派别 | 核心判断 | 关键证据（具体要素） | 应期 |
（逐派一行；证据必须带具体术数要素）

### 二、质询与辩论
- 共识点：…（哪几派、依据）
- 分歧点：…（哪几派对立、**分歧根源**是什么）

### 三、修正留痕
- {派别}：原判断 → 修正后（触发证据）

### 四、综合结论
- 📌 **共识**（置信度：高）：…
- 🔀 **分歧**（置信度：中/低）：…
- 🎯 **应期**：…
- 🧭 **行动建议**：2-3 条可执行

### ⚠️ 边界声明
（参数完整度 / 未跑体系 / 非科学预测 / 重大决策以现实为准）
```

## 六、风格纪律（用户偏好）

1. **说人话**：白话为主，术数术语作括号注（如"用神壬水（你的财星）"）；**不用文言角色扮演**——不写"老夫观此卦""天乙道兄"这类戏剧化台词（易掩盖算错）
2. **禁无据推演**：每条结论必须挂具体要素或古籍出处
3. **不强行共识**：分歧就是分歧，并列呈现
4. **现实优先**：涉法以律师为准、婚姻/求职以现实为准

## 七、反面清单（不做）

- ❌ AI 手算排盘（案例：六合玄机——地基不可靠）
- ❌ 文言角色扮演式输出（用户无此需求，且降低可读性）
- ❌ 空话式证据（"气场""感觉""大概"）
- ❌ 强行"所有体系一致"（编造共识）
- ❌ 单体系下绝对化判词（"必死""大凶""命中注定"）
