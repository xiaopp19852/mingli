# 命理综合解读（Mingli Synthesis）

本 skill 是**编排层**，不直接做排盘计算。它负责：
1. 收集并校验输入（生辰、性别、问事时间、问题）
2. 按需调用六个子 skill，每个子 skill 输出**统一数据契约（YAML）**
3. 对多系统结果做交叉验证（共识 / 分歧）
4. 输出三块式解读：共识项、分歧项、落地行动建议

## 触发条件

用户出现以下任一诉求时加载本 skill：
- "测运势 / 算一卦 / 看命 / 看盘 / 综合分析一下"
- 想同时参考多个体系（八字+紫微+星座…）
- 对某个具体问题（事业、感情、财运、健康、择时）寻求多角度参考

## 计算层（mingyu MCP — 已接入 2026-08-07）

**优先用 mingyu MCP 做一切排盘计算**（`mcp_mingyu_*` 工具），不再手工推算：

| 需求 | 调用工具 |
|---|---|
| 八字排盘+解读提示词 | `mcp__mingyu__bazi_prompt`（深度首选 `bazi_ziwei_prompt` 八字紫微合参） |
| 紫微斗数 | `mcp__mingyu__ziwei_prompt` |
| 奇门遁甲 | `mcp__mingyu__divine_qimen` / `qimen_prompt` |
| 六爻 / 梅花 / 大六壬 / 小六壬 / 金口诀 | `divine_liuyao` / `divine_meihua` / `divine_liuren` / `divine_xiaoliuren` / `divine_jinkoujue`（+对应 `*_prompt`） |
| 西方占星 | `mcp__mingyu__astrolabe_prompt`（含双盘 `astrolabe_synastry_prompt`） |
| 塔罗 / 雷诺曼 / 灵签 | `divine_tarot` / `divine_lenormand` / `divine_ssgw`（+对应 `*_prompt`） |
| 择日 / 生肖流年 / 八宅 / 太乙 / 七政四余 / 玄空 / 住宅风水 | `divine_almanac` / `metaphysics_zodiac` / `metaphysics_bazhai` / `metaphysics_taiyi` / `metaphysics_qizheng` / `metaphysics_xuankong` / `metaphysics_residential` |
| 真太阳时 / 节气 / 月相 / 干支 / 神煞 / 五行 | `calendar_true_solar_time` / `calendar_solar_term` / `calendar_moon_phase` / `foundation_ganzhi` / `foundation_shensha` / `foundation_wuxing` |

**使用要点**：
- 每个 `*_prompt` 工具返回 `result`（结构化数据）+ `prompt`（可直接喂给 AI 的解读提示词）——把 `prompt` 内容作为解读依据
- 排盘参数：`dateType: solar|lunar`、`year/month/day`、`gender: male|female`、时辰用 `timeIndex`（0=早子时...12=晚子时）或 `birthHour/birthMinute + useTrueSolarTime: true + birthLongitude`（真太阳时模式）
- 出生时辰未知时**不要自行补时辰**：八字可保守分析，紫微/合参需用户补足时辰
- 该 MCP 输出的证据链风格（主证/反证/限制）与我们诚实原则一致，直接沿用
- 本 skill 的自带脚本引擎（bazi-paipan/scripts/paipan.py）作为 MCP 不可用时的回退

## 工作流程

### 第 1 步：采集输入（必须问清，缺项可跳过但要在输出中注明）

| 字段 | 必填 | 说明 |
|---|---|---|
| birth_solar | 是 | 公历出生日期 + 时间（精确到小时，分钟可选） |
| birth_place | 推荐 | 用于真太阳时修正和星盘经纬度；未知则用东八区 |
| gender | 是 | 影响八字大运顺逆、部分神煞 |
| ask_time | 推荐 | 问事时间（奇门、周易、塔罗需要）；缺省用当前时间 |
| question | 是 | 想问什么（事业/感情/财运/健康/择时/整体） |

注意：用户给农历/阴历生日时，先换算为公历（可说明换算结果供用户确认）。

### 第 2 步：门派适配（按问题类型启体系，不无脑全跑）

| 问题类型 | 启用体系 | 必需信息 |
|---|---|---|
| 一生格局/命盘 | 八字（子平+盲派双口径）+紫微+占星 | 生辰+性别 |
| 流年/流月/流日 | 八字流年月日+紫微流年月 | 生辰 |
| 单次决策问事 | 奇门+梅花（可加六爻/大六壬） | 问事时刻+事项 |
| 寻人/寻物/官非诉讼 | 奇门（`qimen_yongshen` 14 事类）+六爻 | 问事时刻 |
| 婚恋/合盘 | 八字合盘+紫微双盘+占星合盘 | 双方生辰 |
| 住宅/办公风水 | 八宅+玄空+流年飞星 | 坐向+建造年+命卦 |
| 择日/择时 | 黄历择日+奇门 | 事项+时段+参与人生辰 |

默认：命盘类=八字+紫微+占星；问事类=奇门+梅花；用户指定则从其要求。

**⚙️ 前提铁律**：排盘一律走引擎（`mingyu` / `mingpan` / `pai_pan.py`），**AI 绝不手工推算四柱或卦象**；四柱须多引擎交叉一致——反面教训：GitHub「六合玄机」让 AI 手算排盘，"圆桌再漂亮，地基是错的"（其免责声明亦自认紫微安星/大六壬九宗门可能误差）。

子 skill 加载方式：逐个 `skill_view(name=...)` 读取其 SKILL.md 中的算法与输出格式，按其中的流程执行。

### 第 3 步：统一数据契约

每个子 skill 必须输出以下 YAML 结构（子 skill 各自填充）：

```yaml
system: bazi | ziwei | qimen | astrology | zhouyi | tarot
input_used:
  birth_solar: "1990-08-07 14:30"
  birth_place: "北京"
  gender: "男"
  ask_time: "2026-08-07 10:00"
  question: "事业"
result:              # 各系统核心结果（字段随系统而异）
  ...
key_points:          # 3-5 条该体系最值得注意的要点（中文，面向解读）
  - "..."
confidence: high|medium|low   # 按下方"置信度三档"判定
disclaimer: "本系统输出为传统文化符号解读，非科学预测，仅供参考。"
```

**置信度三档标准（必标）：**

| 档位 | 成立条件 | 输出要求 |
|---|---|---|
| **高（铁断）** | ≥3 独立体系一致 **且** 有古籍明文/引擎证据链 **且** 能给出可验证的时间窗或事件 | 敢锁死；不用"可能/也许"式回退话术（铁断纪律） |
| **中（倾向）** | 2 体系一致，或多数一致但存在明确分歧点 | 给倾向判断 + **标注分歧点**（谁不同意、为什么） |
| **低（待验证）** | 信息不全（时辰未定/参数缺失）／仅单一体系支持／严重冲突 | 标注**待验证条件**（什么现实信息能确认或推翻） |

### 第 4 步：圆桌合参（五轮）

**第 1 阶段·隔离解读**：各派独立推演，**严禁交叉污染**（子平用格局用神、盲派用象法刑冲、紫微用星曜四化、奇门用门星神格）

**五轮**：
1. **R1 立论**——每派：核心判断（吉/凶/中平/参半）+ **2-3 条具体证据**（必须挂术数要素，如"用神午火月破日克"）+ 应期
2. **R2 质询**——**每派至少质询两派**：求同 + 指异（引本派技术理由）
3. **R3 辩论**——聚焦 top 2-3 矛盾，**目标是搞清"为什么分歧"**（体系视角差异 ≠ 真矛盾）
4. **R4 修正**——各派可改判，**留痕**（原判断 → 修正后 → 触发证据）
5. **R5 综合**——归并统一维度：**共识**（≥3 体系一致，最高权重）· **部分支持**（2 体系）· **分歧项**（原样并列，**不强行调和**）

**输出风格**：说人话（术数术语作括号注）；**不用文言角色扮演**（不写"老夫观此卦"式台词）。

完整五轮规则、证据合格标准、输出模板、反面清单 → **`references/roundtable-protocol.md`**

### 第 5 步：输出格式

**判词质量规范（吸收自 ShenSuan 神算 skill，必守）：**

1. **每法判词最少 400 字**：每个系统单独一篇判词，禁止用表格替代正文，条与条之间用 `---` 分隔
2. **八面硬性输出**：每个系统的判词必须逐项覆盖八面，缺一不可，每面独立成段：
   - **一、格局定位** — 此系统下此命的格局、核心特质
   - **二、性格禀赋** — 禀性倾向、思维模式、情绪底色
   - **三、事业路径** — 适合的领域、发力节点
   - **四、财富格局** — 财源形态、进出节奏
   - **五、人际图谱** — 贵人/小人/合作/竞争
   - **六、感情画像** — 亲密关系模式、相处要点
   - **七、流年节点** — 当下阶段、关键时间窗口
   - **八、行动指南** — 宜至少两条、不宜至少两条，落到可操作行为
3. **好坏都说**：每条判词先优势后隐患，给转化方案，不偏不倚
4. **医易同理**（可选修辞）：判词可用中医/身体比喻辅助表达（限文化修辞，严禁健康建议/食疗推荐/症状诊断）
5. **用词安全**：正文禁止「算命/预测/吉凶/化解/改运/注定/天意」，用「分析/参考/觉察/禀赋特质/可能倾向」替代
6. **八面自检**：每条判词输出前逐项核对八面是否齐全，缺则补全

**综合输出模板：**

```markdown
## 综合解读（{日期} · {问题}）
> 引擎：{mingyu/mingpan/…} ｜ 参数完整度：{已定/时辰待定/…} ｜ 未跑体系：{…}

### 📌 多系统共识（置信度：高）
- 各系统共同指向的 2-4 条（跨系统交叉验证后提炼）

### 🔀 系统分歧（仅供参考）
- 分歧点 + 各系统各自说法

### 🧭 落地建议（行动导向）
- 基于共识的 2-3 条可执行建议（不是"吉凶"判词）
- 时间窗口提示（如有：如"未来 3 个月"）

### ⚠️ 边界声明
- 排盘参数完整度、真太阳时是否修正、哪些系统未跑
- 命理是文化符号体系，不是科学预测；重大决策请以现实依据为主
```

## 与 ShenSuan 神算 skill 的协同

本 skill 侧重**多系统交叉验证**；`shensuan` skill 侧重**单一体系深度判词**（26 法、每法 400 字八面输出）。当用户要求"某系统详细展开"时，调用 `shensuan` 对应分类的判词规范；当用户要求"全面综合"时，用本 skill 编排。两者数据契约兼容（shensuan 的 paipan.py --json 输出可直接喂给本 skill 的 bazi 数据槽）。

## 诚实原则（必须遵守）

1. 所有输出标注"传统文化视角，非科学预测"
2. 系统间矛盾如实呈现，禁止编造"所有体系一致"
3. 不给出"必死/大凶/命中注定"类绝对化判词
4. 排盘算法不完整或参数缺失时，降低 confidence 并明确说明
5. 财务、医疗、法律等重大决策，明确建议咨询专业人士
